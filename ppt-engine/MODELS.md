# Model selection for the ProjectArrakis deck engine

**Research date:** 26 September 2026. **Decision:** use `deepseek/deepseek-v4.1-flash` as the **first planner candidate**, with reasoning disabled, and `google/gemini-2.5-flash-lite` as the low-cost **visual QA candidate**. This is a qualified engineering pick for the *current semantic-plan/native-PPTX pipeline*, not a claim that DeepSeek has the best design taste in the world. **No current tested model/deck reached Ishan's “Peak” bar.** Keep human review of every exported slide, source claims, and native editability. A paid model and a valid PDF do not replace either.

Do **not** run the current engine's DeepSeek planner unchanged and expect this result. The code does not yet send `reasoning: {effort: "none"}` for this model; at its common 5,500-token cap, an initial call used 4,780 output tokens on reasoning and truncated. The successful result came from an explicit reasoning-disabled experimental request. Wire that control, a response limit, cost logging and source/QA gates into the next engine flow before adopting the pick. The current default `google/gemini-2.5-flash` for both roles is paid and does not implement this decision.

## Why this pick, not the previous Ling suggestion

The old Ling recommendation rested on price, a JSON-capable catalog listing and an unrelated HTML probe, not a native deck bake-off. Ishan rejected it as the design planner and asked for GLM, DeepSeek and Gemini Flash-class comparisons. We evaluated those families on the same source packet, photos, response schema and PPTX renderer. Two distinct Ganesh Chaturthi briefs tested a straightforward economy story and a human-first pandal progression. This is a small experiment, not a statistically powered taste ranking. The verdict weights (1) narrative/story and non-repetitive rhythm, (2) factual framing, (3) valid structured plan and rendered result, (4) visual result after deterministic rendering, (5) cost and latency. Geometry was *not* freely model-designed: the same seven-archetype renderer limits everyone.

## The visual critic is a separate decision

Controlled one-slide probe used a clean rendered native slide and the same slide with two planted pixel defects (headline covered and figure altered/overpainted). `google/gemini-2.5-flash-lite`, `google/gemini-3.1-flash-lite` and `google/gemini-3.5-flash` each approved clean and rejected planted, naming two defects. Explanations of the tampered figure were sometimes imprecise. Pair costs were **$0.0004262**, **$0.0007285** and **$0.009042** respectively. The original 2.5 Lite choice remains a sensible cheaper first critic; one pair cannot estimate error-detection sensitivity, and visual inspection must still cover all slides. A visual critic cannot certify whether ₹30,000 crore is a trade projection, an audited number, or a fabricated citation. Check evidence separately. Keep a stronger multimodal fallback only when a broader multi-defect evaluation shows a gain worth its cost.

## External evidence and what it does *not* prove

- Design Arena's anonymous pairwise web/UI comparisons are a useful independent *taste proxy*, **not** PPTX-quality scores. As fetched on 26 September, its [DeepSeek profile](https://www.designarena.ai/models/deepseek-v4-1-flash) reported 7,194 tournaments and 54% overall win rate; its [Gemini 3.5 Flash profile](https://www.designarena.ai/models/gemini-3.5-flash) reported 41,863 tournaments and 54%. The same live pages gave DeepSeek website rank #11 vs Gemini #39, but these use different tournament samples and change over time. [Method](https://www.designarena.ai/about). The GLM 5.2 [case study](https://notes.designarena.ai/how-glm-5-2-beat-fable-5-at-website-design/) explicitly found successful yet recurring website templates. It does not transfer to GLM 5.3 Flash or guarantee slide taste.
- [UniPPTBench](https://arxiv.org/html/2605.17356) separates visual organization from grounded task fulfillment and uses source-aware evaluation; its narrative/style/visual-design stages reinforce staged diagnosis. [DeepSlides](https://aclanthology.org/2026.findings-acl.1524/) tests a design-first/code-later slide workflow against fixed-template/direct-code baselines. These support our *method*, not a DeepSeek-versus-Gemini model ranking. [PPTBench](https://arxiv.org/html/2512.02624v1) addresses PowerPoint layout/design understanding, also not this model bake-off.
- The native reference audit in [DESIGN-KNOWLEDGE.md](./DESIGN-KNOWLEDGE.md) inspected 13 official PPTX files, 228 slides: strong covers, asymmetric fields, purposeful hero art, different information grammars, typography ratios and pacing. Its “Peak” Sales Kickoff reference is far more ambitious than any render in this test. The supplied Slidesgo Gray & Neon source remains preview-only by user choice. These references calibrate the target, **not** a license to copy assets or claims.

## Architecture implications and release gates

The two prompt designs revealed a *renderer ceiling*: all candidates are squeezed through seven semantic archetypes, and the prompt itself nudges the three-card/stat/closing sequence. The model selects archetype, wording, colors and asset, while deterministic code chooses actual geometry. A better model alone cannot create Sales Kickoff-like intentional asymmetry, layered focal art, spatial supply-chain diagram, mixed image collage, editable data visualization or custom rhythm under this contract. Before claiming “Peak,” encode the design knowledge as richer **model-selectable visual verbs and composition families**, not hard-coded topic templates. Preserve deterministic coordinate/text/image/export mechanics and native editable elements. A future test should compare models *again* on the richer engine, with multiple briefs and blind human ratings; the current ranking may change.

Minimum release gate: source-to-claim audit (CAIT projections labeled, overlapping categories not summed, 2024/2025 projections not turned into a measured growth rate); no unattributed fabricated quotes; source URL validation; model plan schema and meaning checks (a `big_stat` needs a value, image-required layouts need an asset); measured text fit and number/unit keep-together; PDF boundary scan; visible pixel inspection of every slide, including image crop, contrast and projector readability; editable object audit in PPTX; explicit cost ceiling and no implicit paid retries. Reject failed plans instead of silently healing their meaning. The current engine passes its 37 local unit tests but is a prototype, not a production release.

**Reproduce the successful planner configuration:** exact model ID `deepseek/deepseek-v4.1-flash`, strict JSON semantic schema, explicit `reasoning: {"effort":"none"}`, bounded output, per-call usage/cost capture. This is a design/implementation contract, **not** a command that the existing CLI already fulfills. For a quick fallback use `google/gemini-3.1-flash-lite`; consider Gemini 3.5 for selective style critique once the visual grammar is richer, not as the default planner at present. No automatic model fallback or hard dollar cap is implemented yet.
