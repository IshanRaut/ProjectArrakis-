# Learning cycle 4: a persistent object can carry a story across slides

Date: 27 September 2026. This note adds one native, motion-specific pattern to the 13-template static audit and companion notes. It does not prescribe animation for every deck.

## Native source and scope

[Sitesh Kumar Samal, Powerpoint_Morphs repository](https://github.com/Sitesh-ks/Powerpoint_Morphs) contains a self-described set of PowerPoint morph designs. I downloaded its [Morph Presentation.pptx](https://raw.githubusercontent.com/Sitesh-ks/Powerpoint_Morphs/main/Morph%20Presentation.pptx), SHA-256 `24a78ed030891c93b47677fffb2de9cd70b05b2805829127cbcc2d89caa9fd3c`, six slides, and [Morph transition -Picture wheel-.pptx](https://raw.githubusercontent.com/Sitesh-ks/Powerpoint_Morphs/main/Morph%20transition%20-Picture%20wheel-.pptx), SHA-256 `ad43e7b34d497d6251ec2472669880d9dfb9ba8d60490249025afc869d916e5e`, seven slides. These are maker examples, **not award winners or evidence of a top-selling deck**. I inspected both native OOXML slide trees/transitions and rendered all six slides of the first file in LibreOffice. I did *not* validate PowerPoint slideshow playback; the static PDF shows visual states, not the in-between motion. Microsoft’s [Morph support guide](https://support.microsoft.com/en-us/powerpoint/training/use-the-morph-transition-in-powerpoint) grounds expected PowerPoint behavior and version caveats separately. Source art/images have no independently checked reuse rights; the repository's [MIT LICENSE](https://github.com/Sitesh-ks/Powerpoint_Morphs/blob/main/LICENSE) should not be assumed to clear every depicted photograph.

## Novel design grammar: persistent hero, changing focus

In *Morph Presentation*, slide 1 opens with seven radial photographic sectors forming a central wheel around the label 'Events'. On slide 2 the wheel shifts left and exposes a large 'march' heading. On slides 3-6 it remains cropped on the left, but the highlighted sector and right-side topic/illustration change: breakfast, monument, landscape, relaxing. The recurring seven sectors appear in each slide’s native picture tree under the names `Picture 70`, `73`, `75`, `77`, `79`, `81`, `83`; each slide carries a `p:transition` with child `p159:morph option="byObject"`. The second file uses an analogous seven-sector radial motif and the same morph transition type. This differs from a copied footer, ordinary chapter divider, static three-card agenda, or a generic fade: **one object family acts as a spatial memory and a live navigation metaphor, moving from overview to focused chapter while keeping identity**. In the first rendered file, the navy background and cropped wheel keep stable scene continuity while each right-hand visual fills a new narrative role.

The transition belongs to each destination slide, not to a webpage animation. Microsoft says Morph needs consecutive slides with at least one object in common (duplicating the first slide, then moving the object on the second is its simple setup); Morph can move text/shapes/pictures but does not morph charts. PowerPoint version support differs between creating and merely playing Morph. That documentation supports the technique, but the exact interpolation of these two specific files remains unverified until native PowerPoint playback is tested. LibreOffice PDF cannot prove the motion works.

**Agentic engine contract:** a planner should choose this grammar only where overview -> focused segment is meaningful, e.g. a product ecosystem, a journey map or a sequence of scenes. Label the persistent source object(s) and each chapter target in the shape manifest. When duplicating/adapting, preserve matching objects, their media relationships and transition XML; move/resize/crop consistently from state to state, rather than rebuilding a similar-looking but unrelated wheel. Verify the slide sequence and object identity after edits. Treat an unsupported viewer, printed/PDF delivery, or excessive motion as a different mode: every *static* frame must still communicate its message, with sufficient contrast and readable text, even if Morph never plays. Avoid image licensing assumptions and replace demo text/photos as needed. A change to shape names/relationships or slide order can break intended continuity, so implement only after playback QA in the target viewer. No browser-based editing or paid model call follows from this research.

## Related source comparison and rejections

- The existing 13-deck sample records push/fade transitions but zero native object animation, and the previous broadcast-style note correctly calls out the gap between an 'Interactive' title and a static export. This source actually has a Morph transition element on every inspected slide; **still** no claim that a rendered PDF demonstrates animation.
- [Microsoft PowerPoint Zoom guidance](https://support.microsoft.com/en-us/powerpoint/use-zoom-for-powerpoint-to-bring-your-presentation-to-life) describes summary, slide and section zoom, with optional 'Return to Zoom'. This is a related but different non-linear navigation model. I did not obtain and validate a clean native Zoom PPTX; one community file was encrypted and excluded. Do not present it as a dissection.
- I downloaded and rendered [Grunge Style](https://www.slidescarnival.com/template/grunge-style/34264) ([PPTX](https://www.slidescarnival.com/download/sc00506/grunge-style/pptx), 25 slides) and [Lettering Designs for Marketing](https://www.slidescarnival.com/template/lettering-designs-for-marketing/33649) ([PPTX](https://www.slidescarnival.com/download/sc00496/lettering-designs-for-marketing/pptx), 29 slides). Torn-paper collages, layered decorative letters and vivid modular editorial pages are visually appealing but overlap already recorded collage/editorial/section grammars and the comic-note’s layered scene treatment. No new pattern was claimed from them. [Print Media Advertising](https://www.slidescarnival.com/template/print-media-advertising-slides/328486) ([PPTX](https://www.slidescarnival.com/download/sc03128/print-media-advertising-slides/pptx), 18 slides) was natively parsed but not rendered; no visual verdict.
- Agency case studies were sampled as leads, not native dissections: [Ochi's Premium Blend template case](https://ochi.design/case/presentation-template-premium_blend/) describes a 40-layout PowerPoint system designed from employee use cases, and [La boîte à slides' METRON case](https://laboiteaslides.fr/en/works/metron-interactive-presentation) describes an editable non-linear sales deck. No source PPTX was available to validate their mechanics. These are agency-authored descriptions, not independent quality measurements.
